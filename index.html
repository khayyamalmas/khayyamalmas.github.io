Three tools that close the loop

Each one takes a single task identifier as its only input and does the rest — reading the systems the team already works in, and writing back to them.

Specification → Test cases

Reads the requirement document behind a task, builds a numbered requirement inventory, then applies ISTQB design techniques — equivalence partitioning, boundary values, decision tables, state transition, role-permission matrices — to produce the full case set. It then creates the folder, imports every case, links each one back to its task and assigns the owner from the task's assignee.

OutputsImport file · review workbook · RTM
ReadsTask tracker · knowledge base · test management
GuardWrites only on approval

Test cases → Automation

Turns approved manual cases into Playwright and TypeScript: groups them by screen, plans the Page Objects, resolves real selectors from the frontend source or a recorded codegen session rather than inventing them, and emits page classes plus spec files wired to Allure reporting.

OutputsPage Object classes · tagged spec files · Allure integration
StackPlaywright · TypeScript · Page Object Model
GateType-check clean · spec count = case count

Failures → Defects

Reads execution results and, for failed cases only, opens a defect under the parent task: routed to the responsible frontend or backend developer, carrying a recorded browser session as evidence, and linked both to the exact specification section and back to the case that failed.

OutputsAssigned defect with evidence, specification anchor and case link
EvidenceRecorded session — video plus network, console and error logs
RuleEvidence environment overrides the case
Field notes

What I learned the hard way

Integration rules found by piloting against a real Data Center instance, then written into the tooling so nobody has to rediscover them.

Owner is a user key, not a username
The test management REST API rejects a username for the owner field. Assignment only succeeds with the internal user key, read from the task's assignee first.
Estimates are milliseconds
A fifteen-minute case is 900000. Anything that looks like a clock value is silently wrong.
Priority vocabularies differ per project
"Medium" simply does not exist in some projects. One pilot case validates the real vocabulary before a bulk import fails halfway through.
